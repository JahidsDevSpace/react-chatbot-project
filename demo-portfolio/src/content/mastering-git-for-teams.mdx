# More Than Just `git commit`

Git is an essential tool for any software developer, but using it effectively in a team environment requires more than just knowing a few commands. A solid Git workflow ensures that everyone can work in parallel without creating chaos.

## The Feature Branch Workflow

The most common and effective workflow is the **Feature Branch Workflow**. It's simple, safe, and scales to teams of any size.

1.  **Create a Branch:** Before starting any new work (a feature, a bugfix), create a new branch from the `main` (or `develop`) branch. Give it a descriptive name.

    ```bash
    # Make sure your main branch is up-to-date
    git checkout main
    git pull origin main

    # Create your new feature branch
    git checkout -b feature/user-authentication
    ```

2.  **Do the Work:** Make your changes and commit them to your feature branch. Write clear, concise commit messages.

    ```bash
    git add .
    git commit -m "feat: Add login form component"
    ```

3.  **Push and Open a Pull Request (PR):** Push your branch to the remote repository and open a Pull Request on GitHub, GitLab, or Bitbucket.

    ```bash
    git push -u origin feature/user-authentication
    ```

4.  **Review and Merge:** Your teammates can now review your code, leave comments, and suggest changes. This code review process is critical for maintaining quality. Once the PR is approved, it can be merged into the `main` branch.

## Why This Works

- **Isolation:** Your work is isolated on its own branch. It doesn't affect the main codebase until it's ready and approved.
- **Collaboration:** Pull Requests are the central hub for discussing changes and ensuring everyone is on the same page.
- **Clear History:** The `main` branch remains a clean, linear history of completed features, making it easy to track what was changed and when.

By adopting a simple workflow like this, your team can move faster, reduce conflicts, and build a more stable and maintainable product.
